Mini Project Report
Hotel Management System
A Java web application for managing hotel room inventory, guest reservations, occupancy analytics, and automated billing checkout.

1.1 Background

In the modern hospitality sector, maintaining an accurate and frictionless guest record system is essential to guest satisfaction and hotel operational revenue. Conventional approaches to hotel front-desk administration rely on physical ledgers or standalone spreadsheets. These legacy workflows frequently introduce duplicate room assignments, manual billing computation errors, misplaced guest contact records, and severe delays in identifying vacant versus occupied rooms during peak check-in windows.

1.2 Problem Statement

A manual hotel management register can be arduous to maintain, lacks real-time synchronization between desk clerks, and offers no automated mechanism to generate itemized checkout bills. Front-desk personnel must manually verify stay duration, compute per-night multipliers, and physically check rooms before updating room availability. The LuxeStay project delivers a high-speed, centralized web solution where hotel clerks can view live occupancy metrics, allocate vacant rooms with zero collision, and execute checkouts with instant automated receipts.

1.3 Objectives

  • Provide a centralized relational database for room inventory and active guest bookings.
  • Enforce authenticated sessions so that room administration and booking actions are restricted to authorized hotel staff.
  • Allow staff to dynamically register new rooms with customizable categories (Single, Double, Suite) and nightly pricing.
  • Prevent double-booking by presenting only vacant rooms in reservation forms and dynamically managing room availability status.
  • Automate stay charge computations (nights × pricePerNight) and generate itemized digital receipts.
  • Present an executive dashboard with dynamic KPI cards and an SVG occupancy donut chart for administrative decision making.
  • Demonstrate the implementation of Jakarta Servlet 6.0, Apache Tomcat 10.1, JDBC, MySQL, and asynchronous Fetch API in a decoupled web architecture.

1.4 Scope

Included in Current Release:
  • Staff authentication & secure session lifecycle.
  • Live Executive Dashboard with real-time KPI metrics (Total, Available, Booked, Potential Revenue).
  • Dynamic SVG donut chart visualizing room occupancy ratios.
  • Room inventory addition with validation (Room number, category, pricing).
  • Guest reservation workflow with phone validation and stay duration.
  • Automated checkout with printable billing receipt breakdown.

1.5 Intended Users

Hotel Staff & Receptionists: Handle day-to-day guest arrivals, allocate vacant rooms, monitor active bookings, and process checkout billings.

Hotel General Manager: Reviews room occupancy metrics, potential nightly revenue, registers new rooms, and oversees hotel operational efficiency.

3.3 Request Processing Pattern

When a staff member triggers an action (such as confirming a room booking), the browser dispatches an asynchronous HTTP POST call via the JavaScript fetch() API with form-urlencoded payloads. The Jakarta Servlet HotelServlet intercepts the request at /api/book, extracts parameter values, and calls the static method DBManager.bookRoom(). The database manager executes a parameterized PreparedStatement against MySQL, ensuring zero risk of SQL injection. Upon completion, the servlet returns a JSON payload (e.g., {"success":"..."}), prompting the client-side UI to update the DOM and refresh dashboard metrics instantaneously without full page reloads.

Database Design
Relational Schema & Data Operations
Structure of hotel_db database, data dictionary, and transactional operations.

4.1 Database Overview

The project utilizes a dedicated relational database named hotel_db configured with UTF-8 Unicode encoding (utf8mb4_unicode_ci). Room specifications, pricing, reservation states, and active customer metadata are managed in the rooms table.

DATABASE: hotel_db │ └── rooms ├── room_number VARCHAR(20) NOT NULL PRIMARY KEY ├── type VARCHAR(20) NOT NULL DEFAULT 'Single' ├── price_per_night DECIMAL(10,2) NOT NULL ├── status VARCHAR(20) NOT NULL DEFAULT 'Available' ├── customer_name VARCHAR(100) DEFAULT '' ├── customer_phone VARCHAR(20) DEFAULT '' └── number_of_nights INT DEFAULT 0

4.2 Data Dictionary — rooms Table

Field Type Constraints Purpose & Description
room_number VARCHAR(20) PRIMARY KEY, NOT NULL Unique physical room identifier (e.g., '101', '204').
type VARCHAR(20) NOT NULL, DEFAULT 'Single' Category of room: 'Single', 'Double', or 'Suite'.
price_per_night DECIMAL(10,2) NOT NULL Nightly room rate in Indian Rupees (₹).
status VARCHAR(20) NOT NULL, DEFAULT 'Available' Current status flag: 'Available' or 'Booked'.
customer_name VARCHAR(100) DEFAULT '' Full name of the currently staying guest.
customer_phone VARCHAR(20) DEFAULT '' Contact telephone number of registered guest.
number_of_nights INT DEFAULT 0 Duration of current stay used for bill generation.

4.3 Data Operations

  • Create (Add Room): Staff enters room details; DBManager.addRoom() executes an INSERT INTO rooms statement with default status 'Available'.
  • Read (Load Inventory & Analytics): DBManager.loadRooms() queries all rooms via SELECT * FROM rooms, mapping results to Room entity objects for JSON serialization.
  • Update (Book Room): When reserving an available room, DBManager.bookRoom() updates status to 'Booked' and sets customer name, phone number, and stay duration.
  • Reset (Checkout): Upon guest checkout, DBManager.checkoutRoom() resets status back to 'Available' and clears customer details and nights to zero.

5.2 Important Implementation Details

  • Automated Database Bootstrap: DBManager.java automatically creates the hotel_db database and rooms table on server boot if they do not exist.
  • Zero-Dependency JSON Serialization: Room.java formats clean JSON representations natively, eliminating dependencies on third-party libraries like Jackson or Gson.
  • Prepared Statements: All database mutations and queries use parameterized JDBC statements to guarantee protection against SQL injection attacks.
  • Automated One-Click Batch Deployment: The included run.bat script detects JDK 17+, resolves Tomcat 10.1 and MySQL Connector/J, compiles Java classes against the Jakarta Servlet API, stages files into build/, and boots the Tomcat web server.

5.3 Setup Summary

  1. Install JDK 17 or higher and ensure the JAVA_HOME environment variable is set.
  2. Start the local MySQL 8.x database service on port 3306.
  3. Verify database credentials in src/com/hotel/util/DBManager.java (default: root / root123).
  4. Open a command prompt in the project root and execute run.bat.
  5. Open a web browser and navigate to http://localhost:8080/.

Limitations & Future Enhancements
Constraints & Strategic Roadmap
Current system boundary conditions and prospective architectural improvements.

6.1 Current Limitations

  • Demonstration Authentication: The authentication mechanism utilizes client/administrative credentials (admin / admin123) without multi-tier role hierarchy (e.g., General Manager vs. Front Desk vs. Housekeeping).
  • Single Flat Entity Table: Booking information is recorded directly onto the rooms table. Historical booking data is reset upon checkout rather than archived into a dedicated historical reservations ledger.
  • Absence of Online Payment Gateway: Checkout computations are fully automated, but payment collection remains manual (cash or external card machine) without Stripe or Razorpay integration.
  • Single Node Local Deployment: Deployment batch scripts target local Apache Tomcat instances without cloud load balancing or container orchestration (Docker/Kubernetes).

6.2 Future Enhancements

Security

  • BCrypt salted password hashing in database.
  • Role-based access control (RBAC) servlet filters.
  • CSRF token validation for state-modifying requests.
  • Encrypted HTTPS communication and secure session cookies.

Workflow

  • Dedicated historical bookings ledger table.
  • Date-range reservation calendar to book future dates.
  • Integrated payment gateway (Razorpay / Stripe).
  • Automated email / SMS reservation confirmations.

Usability

  • PDF receipt download and thermal printer support.
  • Room search and filtering by price and amenities.
  • Guest self-service booking portal on mobile web.
  • Dark / Light theme personalization toggle.

Reliability

  • Automated JUnit test suites for DAO and servlets.
  • HikariCP high-performance JDBC connection pooling.
  • Docker containerization for rapid cloud deployment.
  • Centralized logging with Log4j and automated DB backups.
Strategic Objective: Evolve the LuxeStay Hotel Management System from an agile academic demonstration into a secure, multi-property cloud management system equipped with audit trails, future reservation scheduling, and self-service guest check-ins.

7.1 Conclusion

The Hotel Management System (LuxeStay) demonstrates how modern Jakarta EE web architectures can simplify, organize, and expedite front-desk operations in hospitality environments. By harmonizing Java Servlets, Apache Tomcat 10.1, JDBC PreparedStatement security, MySQL 8.x, and an intuitive Single-Page Application interface, the system delivers:

  • Reliable, zero-collision room inventory management and live status tracking.
  • Instantaneous stay charge calculations eliminating human billing errors at checkout.
  • Executive dashboard clarity through high-level KPI cards and dynamic SVG room occupancy visualizations.
  • An automated, hassle-free local compilation and deployment pipeline via Windows batch scripts.

The system fully fulfills its academic project objectives, maintaining clean separation between presentation, controller, and persistence layers, while providing a clear architectural foundation for enterprise enhancements.
